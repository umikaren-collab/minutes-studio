# 議事録工房

録音・動画・PDFと会議情報から議事録を作成し、Wordで保存するWebアプリ。Wordの差し込み書式と印刷設定に対応。

招待制で運用する。管理者（オーナー）が相手ごとに**招待コード**を発行し、コードを持っている人だけが議事録を作成できる。AIは管理者の Gemini API キー（有料枠）を使い、利用者がキーを用意する必要はない。

- 自分で設置して使いたい場合は [docs/SETUP.md](docs/SETUP.md) を参照。

## 利用者向け

1. 管理者から受け取ったURLを開く。
2. 「利用コード」欄に受け取ったコードを入れて「確認」を押す（コードはその端末のブラウザーに保存される）。
3. 会議情報を入れ、録音・資料を選び、送信への同意にチェックして「議事録を作成する」を押す。
4. プレビューで確認・修正し、Wordでダウンロードする。

画面の「ご利用にあたって」に、データの扱いと注意事項を表示している。

## 管理者向け（運用）

`/admin` にオーナーのChatGPTアカウントでログインする。

**APIの設定**
- Gemini APIキーと使用モデルを登録する。キーはモデル情報APIで利用可否を確認してからAES-GCMで暗号化してD1に保存し、全文は画面・APIレスポンスに出さない。
- **無料枠のキーは使用できない。** 無料枠では送信内容がGoogleの製品改善に利用される場合があるため。Google AI Studioでプロジェクトの課金を有効にし、「課金を有効にしたGoogle Cloudプロジェクトのもの」にチェックを入れる（Google側から自動判定はできないため申告制）。チェックがないと利用を受け付けられず、サーバー側でもアップロード開始と生成を拒否する。新しいキーを入力するとチェックは外れる。
- **全員合計の1日の上限回数**（1〜200回、既定5回）を設定する。API料金の上限の目安になる。

**招待コード**
- 相手の名前（管理用のメモ）と1日の回数（1〜50回）を入れて発行する。コードは発行時に一度だけ表示される。「コードとURLをコピー」で相手に送る文面をコピーできる。
- DBにはコードのハッシュだけを保存する。忘れた場合は削除して発行し直す。
- 一覧で本日の利用回数・最終利用日時を確認し、回数の変更・停止・再開・削除ができる。管理用のメモは利用者には表示しない。
- コードは読み間違えやすい文字（0/O、1/I/L）を除いた16桁。入力時の小文字・ハイフンの有無は区別しない。

利用者にはURLとコードを伝える。サイト自体の閲覧範囲はSitesのアクセス設定で決める。

## 回数の数え方と制限

- 1回 = アップロード開始から生成まで。開始後の失敗（API失敗・入力上限超過など）も1回と数える。自動再試行はしない。
- コード別の上限と全員合計の上限の両方を満たすときだけ開始できる。全体の上限に達した場合、コード側の回数は戻す。
- コードが誤っている・停止中・無料枠のキー・資料の形式違反の場合は、回数を消費せずに拒否する。
- 回数はD1の条件付き更新で数えるので、同時に送信されても上限を超えない。日本時間0時にリセット。
- 資料は1ファイル200MB、最大5件・合計500MBまで。4MBずつ分割してサーバー経由でGoogle Files APIに転送する（サーバーはファイル全体をメモリーに読み込まない）。
- 入力は1,000,000トークンまで、出力は32,768トークンまで。生成のたびにモデル情報APIで選択モデルの入出力上限を取得し、小さいほうを使う（取得できない場合は出力8,192トークン）。生成の待ち時間は最大5分。

## データの扱い

- 会議情報・資料は、生成時にGoogle Gemini API（有料枠）へ送信する。
- アプリのDBに保存するのは、日付ごとの利用回数、招待コードのハッシュ・管理用メモ・回数設定・最終利用日時、暗号化済みAPI設定、アップロードの一時的な進捗だけ。会議資料や議事内容は保存しない。
- アップロードの確認用トークンはハッシュのみ保存し、2時間で失効する。Google側の一時ファイルは生成完了・中止時に削除し、Google Files APIの自動削除期限でも消える。

## 印刷設定

標準WordではA4・A3・JIS B5、縦横、余白、本文文字サイズ、行間を反映する。差し込み式Word書式は初期状態で既存設定を維持し、チェックを外すと全セクションの用紙・向き・余白だけを上書きする。ページ数、印刷部数、両面印刷はWordで確認・設定する。

## 開発

- `npm test`：テスト（Node.js 22.13以上。D1の代わりに `node:sqlite` にマイグレーションを適用して検証）
- `npm run lint`：lint
- `npm run format`：整形（Prettier）
- `npm run db:generate`：スキーマ（`db/schema.ts`）の変更からマイグレーションSQLを生成

ローカルでの起動手順は [docs/SETUP.md](docs/SETUP.md) を参照。
